# Appcircle CodePush and Native Update

<CheckedLine slug="appcircle-codepush" />

Appcircle puts React Native OTA updates inside the same platform that builds and distributes the app, and it runs on Kubernetes or OpenShift if your company wants it in-house. Rollout percentages and rollbacks sit next to the build pipeline. We don't build apps at all, and we don't serve React Native.

## Keeping the pipeline, changing the updater

Appcircle builds and distributes; we don't. If you want to keep its pipeline and move only the live updates, a React Native app on Android can: the [React Native SDK](/frameworks/react-native) loads a signed bundle, and a [`deploy`](/reference/cli/deploy) step after the build publishes it. iOS isn't ready yet, so an app that needs iOS updates keeps Appcircle's.

[How OTA updates work](/concepts/how-ota-updates-work) explains what a bundle can and can't change.

## The facts, dated

Appcircle's pages didn't state device-verified signing, automatic rollback, delta updates, an in-app store update flow, a review prompt, background checks, a CLI plus HTTP management API, or Capacitor, Flutter or native app support, so those rows are left out.
