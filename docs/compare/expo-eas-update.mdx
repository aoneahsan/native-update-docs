# EAS Update and Native Update

<CheckedLine slug="expo-eas-update" />

EAS Update ships updates to React Native apps built with `expo-updates`, and its branches, channels and rollbacks are wired into the Expo toolchain you already build with. If your app is on Expo, that's the right tool.

## Expo apps stay on Expo

EAS Update is built into `expo-updates`, and we haven't tested our SDK in an Expo app, so an Expo project is better off where it is.

A bare React Native app on Android is another matter. The [React Native SDK](/frameworks/react-native) swaps the bundle the app loads for a signed one from Native Update, rolls back a bundle that never confirms its start, and runs the Play update and review flows. Releases go out with [`deploy`](/reference/cli/deploy) and a rollout percentage, the way EAS branches and channels work for you now. On iOS the SDK isn't ready, so an app that needs iOS updates today stays where it is.

## The facts, dated

Expo's pages didn't state automatic rollback, delta updates, an in-app store update flow, a review prompt, background checks, a CLI plus HTTP management API, or Capacitor, Flutter or native app support, so those rows are left out.
