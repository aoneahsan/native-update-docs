# AppsOnAir and Native Update

<CheckedLine slug="appsonair" />

AppsOnAir is one toolkit for native, Flutter and React Native apps. Alongside CodePush-style releases it distributes test builds, forces a critical update and sends push. That spread of stacks is exactly what we don't have.

## If you're on AppsOnAir today

On Android, each of your stacks has a package here: the [React Native SDK](/frameworks/react-native), the [Flutter SDK](/frameworks/flutter) and the [native Android SDK](/frameworks/native-android). They do live updates, the Play in-app update flow (AppsOnAir's forced update) and the review prompt. We don't distribute test builds or send push, and the SDKs' iOS side isn't ready, so an app that needs those stays put.

For a Capacitor app, [your first update](/tutorials/first-ota-update) is a single walk-through from install to a signed bundle on a device.

## The facts, dated

AppsOnAir's pages didn't state device-verified signing, automatic or manual rollback, percentage rollouts, channels, delta updates, self-hosting, a review prompt, background checks, or Capacitor support, so those rows are left out.
