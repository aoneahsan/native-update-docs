# Moving from Capawesome Cloud

<CheckedLine slug="capawesome-cloud" />

Capawesome Cloud signs bundles with an RSA key pair too, so the release flow will feel familiar. Don't reuse the old key: make a new pair for Native Update, so that each service's bundles can only ever verify against its own key.

If you host bundles on your own CDN through Capawesome and want to keep that shape, read [Backend overview](/backend/overview) first. On Native Update that means running your own server against the [API contract](/backend/api-contract), which is more work than a storage setting.

## 1. Add the plugin and a key

```bash
yarn add native-update
npx cap sync
npx native-update keys generate --type rsa --size 4096
```

Requirements are on the [installation page](/getting-started/installation). Create your app on [the dashboard](https://nativeupdate.aoneahsan.com/login) and copy its API key.

## 2. Swap the live update calls

Take the Capawesome live update calls out of your boot code and follow the [Quick Start](/getting-started/quick-start). The two calls that matter:

```ts
await NativeUpdate.notifyAppReady();
const result = await NativeUpdate.sync();
```

Your other Capawesome plugins are unaffected. If you use its App Update or App Review plugins as well, [that page covers those](/compare/capawesome-app-update-review).

## 3. Recreate your release tracks

Dev, staging, production and any customer tracks become [channels](/how-to/manage-channels). Rollouts start at the percentage you pass per release.

## 4. Ship the store build, then release

The old plugin comes out in one store build. After that:

```bash
npx native-update deploy ./dist --app com.example.app --rollout 5 --wait
```

Set up [the token and the CLI](/reference/cli/deploy) in CI first. Rollback is [per release, per channel](/how-to/roll-back-bundle).
