## A pattern the catalogue lacks: a feed that lists unpublished releases (extends SA-P05 / AI-05)

- **Seen:** both hosts. The docs `feed.xml` made one item per `## <version>` changelog heading, with no
  `<pubDate>`, including builds the same changelog calls superseded or sideloaded. The website feed dated a
  release "the first public release" on 2026-09-01 while the store listing answered 404.
- **Detect:** for each feed item, find the release in the changelog or release data and ask whether it says
  published. Any item without a `<pubDate>`, or for a release the project's own words call prepared,
  superseded or sideloaded, is a FAIL.
- **Fix (Docusaurus, custom plugin):** a release is published only when its heading carries the date
  (`## 1.3.0 — YYYY-MM-DD`); emit items for those alone, each with its RFC-822 `<pubDate>`; zero items is a valid
  RSS 2.0 channel. The browsable `/feed` page shows the changelog's own status paragraph while none is dated,
  so no new words are needed. **Fix (React data file):** `date: string | null` on the release type and one
  filtered `PUBLISHED_RELEASES` list read by the page, the prerendered body and `feed.xml`.
- **Accept:** `curl -s <host>/feed.xml | grep -c '<item>'` equals the number of dated releases; each item has
  a `<pubDate>`.

## Stack-specific fixes

- **Docusaurus 3.10 sitemap:** `changefreq: null, priority: null` in the preset's `sitemap` options drops both
  elements (the option schema accepts `null`); `ignorePatterns` stays for `/tags` and `/search`.
- **Docusaurus local search (`@easyops-cn/docusaurus-search-local` 0.55):** still writes `property=robots`.
  The Rent Party wrapper recipe (`src/theme/SearchPage/index.tsx` around `@theme-original/SearchPage`, adding
  `<meta name="robots" content="noindex, follow">`) worked unchanged; `ComponentProps<typeof SearchPage>` keeps
  `tsc` green without the plugin's types.
- **One product description constant** in `docusaurus.config.ts`, read by the JSON-LD and the default meta
  description, ended an AI-05 mismatch where the JSON-LD carried an older, broader claim.

## Provider behaviour confirmed

- **GitHub Pages, `workflow` → `legacy` switch:** pushing `gh-pages` first and switching the source after did
  not start a build; the site served the old artefact for 3+ minutes. `POST /repos/{o}/{r}/pages/builds`
  queued one and the new tree was live within 20 seconds. `GET /pages/builds/latest` answered 404 throughout.
- **Cloudflare Pages:** for about five minutes (09:28–09:32 UTC, 2026-11-06) every deploy to one project,
  even a one-file directory to a preview branch, failed with `Failed to publish your Function. Got error:
  Unknown internal error occurred.` while another project on the same account deployed. Changing the
  compatibility date did not help; a plain retry did. Retry before changing project settings.
- **IndexNow:** `api.indexnow.org` answered 202 (accepted, key pending validation) for a first submission
  from each host, with `keyLocation` given.

## A probe that lied

- `grep -c '<loc>'` on a minified sitemap counts LINES, so a 17-URL Docusaurus sitemap reads as 1. Count with
  `grep -o '<loc>' | wc -l`.
