# Learnings — lifewell, run 2026-10-29-1956

## 1. Probe lie: `robots-effective` reads "everything allowed" when `Allow: /` comes first

- **Target:** `references/probes.md` → robots-effective.
- **Evidence:** `https://lifewell.aoneahsan.com/robots.txt` (2026-10-29). Every group opens with `Allow: /`, then
  lists `Disallow: /admin/`, `/dashboard`… Python's `urllib.robotparser` is first-match, so it answered `Y` for
  `/admin/x`, `/dashboard/x` and `/settings/x` for every bot. Google's longest-match answers `n`, which is correct.
- **Correction:** evaluate with a longest-match parser (the rule with the longest matching path wins, `Allow` on a
  tie, with `*` and `$` supported). The run's inline version is in the report's evidence (`app/robots-matrix.txt`).
  Keep Python's parser only as a cross-check, and treat an all-`Y` row on a private child path as a probe fault
  until the file has been read by eye.

## 2. Probe lie: `canon-sweep` and `assets` miss everything on a minified Docusaurus page

- **Target:** `references/probes.md` → canon-sweep and assets.
- **Evidence:** `https://lifewell-docs.aoneahsan.com/` serves `<link data-rh=true rel=canonical href=https://…/>`
  and `<meta … property=og:image content=https://…>` with no quotes. The grep probes require a quote after `href=` /
  `content=`, so the sweep reports 0 canonicals, 0 descriptions and no preview image on a page that has all three.
- **Correction:** parse the HTML (`html.parser.HTMLParser`, attributes from `handle_starttag`) instead of grepping.
  Retry each fetch: on a loaded host, two of 100 curls timed out and printed a row of zeros that looked like a FAIL.

## 3. New pattern candidate: SPA rewrites answer with the prerendered HOME document

- **Seen in:** lifewell (`firebase.json`, 80 rewrites → `/index.html`), 2026-10-29.
- **Cause:** after prerendering, `dist/index.html` IS the home page: canonical `/`, `index, follow`. Every rewrite
  that serves it gives a private address with no file of its own (`/dashboard`, `/welcome`, `/auth`) the home page's
  head. Robots blocking those addresses hides it from crawlers, but the signal is wrong, and on any address robots
  does not block it is a duplicate-of-home.
- **Detect:** `curl -s https://<host>/<private-prefix> | grep -oiE '<link rel="canonical"[^>]*>|<meta name="robots"[^>]*>'`
  → a canonical equal to the home URL, or `index`.
- **Fix (Vite + Firebase):** postbuild writes `dist/app.html` (the built template, `noindex`, no canonical) and every
  rewrite points to it; a test asserts each rewrite's destination is `/app.html`.
- **Accept:** each private prefix answers `noindex` with no canonical; listed public pages are unchanged.

## 4. Sitemap still emitting `changefreq` / `priority`

- **Target:** the catalogue's SA-P06 sitemap hygiene (or a small SA-P20). The `-sitemap` skill already says "no
  `<changefreq>` or `<priority>`", but no pattern detects it.
- **Detect:** `grep -cE '<changefreq>|<priority>' sitemap.xml` → must be 0.
- **Seen in:** lifewell app sitemap (100 URLs, both fields on each). Fixed by dropping them from the generator and
  the route records.

## 5. Docusaurus home title doubles the site title

- **Target:** `-docusaurus` (page titles).
- **Evidence:** `src/pages/index.tsx` passed `title="LifeWell Documentation — …"` to `<Layout>`, which appends
  ` | LifeWell Documentation`, so the home `<title>` named the site twice. Pass only the page part.
