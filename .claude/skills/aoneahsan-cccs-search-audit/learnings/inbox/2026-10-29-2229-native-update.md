# Learning inbox — native-update, run 2026-10-29-2229

## 1. A probe that lied: robots-effective reported PASS on a file that failed (target: references/probes.md → robots-effective)
- Evidence: `https://nativeupdate.aoneahsan.com/robots.txt` before 2026-10-30. Every group began `Allow: /`; Python's
  `urllib.robotparser` matches the FIRST rule, so it printed `Y/dashboard/x` for `*` and for every bot although `*` carried
  `Disallow: /dashboard/`, and it hid that 14 named groups carried no Disallow at all.
- Correction: evaluate with Google's longest-match rule (the inline evaluator saved at
  `reports-for-dot-agent/projects/native-update/evidence/2026-10-29-2229/search/robots-effective-longest-match.txt` shows
  the shape: per group, the longest matching Allow/Disallow wins, Allow on a tie). The existing note "first-match
  approximation, confirm surprises by eye" did not catch it: the output had no surprise, it was uniformly wrong.

## 2. A probe that lied: assets extracted `og:image:width`/`height` values as relative URLs (target: probes.md → assets)
- The regex `(og:image|twitter:image)` also matches `og:image:width` and `og:image:height`, so `1200` and `630` were fetched
  as `/1200` and `/630` and reported RELATIVE + 404. Match `property="og:image"` exactly (and `name="twitter:image"`).

## 3. New pattern candidate SA-P20 — private SPA families rewritten to the PRERENDERED home page (target: issue-catalogue.md)
- Seen: native-update (SA-NATIVEUPDATE-002). Firebase `rewrites` sent `/dashboard`, `/admin`, `/auth/**` to `/index.html`, which
  is the prerendered home page, so every private URL answered 200 with `index, follow` and the HOME canonical.
- Detect: GET one URL of each rewritten family; FAIL when the robots meta is not `noindex` or a canonical is present.
- Fix: rewrite private families to a dedicated noindex shell (`app-shell.html`: no canonical, no JSON-LD, empty root) and add
  `X-Robots-Tag: noindex, nofollow` headers for the same sources; the template `index.html` carries no page metadata and the
  generator fails the build if it does. Accept: each family answers noindex with no canonical, live.

## 4. New pattern candidate — a template JSON-LD copied onto every page beside the generated one (AI-05 detail)
- Seen: native-update. `index.html` kept a hand-written SoftwareApplication (iOS, `/docs`, price 0) and postbuild cloned the
  template for every route, so every page had two conflicting SoftwareApplication blocks. Detect: count `"@type":"SoftwareApplication"`
  (both spacings) on the home page; FAIL on more than one. Fix as in 3 (template without metadata).

## 5. Stack recipe — React Router 7 data router: prerender + hydrate (target: aoneahsan-cccs-postbuild-seo-html references)
- `prerenderToNodeStream` OUTLINES large Suspense boundaries (fallback + hidden div + inline `$RC` script) unless
  `progressiveChunkSize: Number.POSITIVE_INFINITY`; the outlined form cannot be hydrated in place.
- `React.lazy` pages inside `<Suspense>` are discarded and client-rendered when any parent update lands before the chunk —
  SILENTLY (no warning even in a development build). Use the route `lazy` property; hydrate after
  `router.state.initialized`. Prove it by tagging the prerendered `<h1>` before boot and checking the same node afterwards.
- An element that enters from opacity 0 is recorded as LCP at its first visible frame, which hydration delays: hero LCP
  median 2.9 s → 0.81 s with the entrance removed (live A/B).
