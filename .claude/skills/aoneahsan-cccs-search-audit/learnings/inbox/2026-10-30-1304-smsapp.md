# Learning inbox — smsapp, run 2026-10-30-1304

1. **New detect step (before any app fix wave): is the live build reproducible?** Compare the host's last release
   time (Firebase: `firebasehosting.googleapis.com/v1beta1/sites/<site>/releases`) with `git log` on the primary
   branch. SMS App's live build (2026-07-13) matched no commit, so every source fix (sitemap, robots, soft 404) was
   already correct in source yet still FAIL live, and a deploy would have shipped three months of unrelated client
   changes against older Firestore rules. Report such records as `still-open: unreproducible live build`, never as a
   source defect. Candidate pattern **SA-P20 — live build ahead of/behind source** (detect: release time vs commits;
   accept: deployed bundle hash equals a commit's build).
2. **Docusaurus `headTags` inside `themeConfig` is silently ignored** (it belongs at the top level of the config):
   the site-wide JSON-LD never shipped. Add to the `-docusaurus` site-config reference as a check.
3. **A single-segment catch-all route (`/:shortKey` short links) makes a soft 404 unfixable at the host** — every
   unknown single-segment path must reach the SPA. Fix by moving short links under a prefix or removing the feature,
   then scoped rewrites + `404.html`. Add to SA-P11's fix list.
4. **Firestore Spark read quota is shared with production:** two full reads of ~34k documents for an import plus one
   analysis read exhausted the 50k/day free quota, so the live app could not read Firestore until the reset. Export
   once to a local file and work from it (owner-visible incident, 2026-10-30). Belongs in
   `aoneahsan-cccs-supabase-schema-design/references/firebase-migration.md` → Traps.
