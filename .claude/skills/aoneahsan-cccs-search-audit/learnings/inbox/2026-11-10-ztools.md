# Learning inbox — ztools, run 2026-11-10-0100

1. **SA-P20 candidate — the app boots into the opposite robots.** A prerendered/served page said `noindex` (shell or
   `X-Robots-Tag`) but the SPA's SEO helper rewrote the meta to `index, follow` with a self-canonical after boot. Probe:
   load the route in a browser, wait for boot, read `meta[name=robots]`; a raw-HTML probe alone gives a false PASS. Fix: one
   private/noindex list read by the build AND by the single robots-meta writer (ztools `src/utils/constants/privateRoutes.ts`).
2. **SPA rewrite target is a document, and it inherits that document's head.** Pages rewrites `→ /` served the home
   document (home canonical, `index, follow`) for every private route. Rewrite to a noindex app shell instead, and make the
   build fail when a rewrite targets anything else.
3. **`canon-sweep` needs `--max-time`.** Without it, a slow page stalls the sweep (114 first-pass `000` rows on the docs).
4. **`assets` regex over-matches `og:image:*`.** `og:image:width/height/type/alt` were counted as images; match the exact
   property.
5. **Two stale calibration rows in `probes.md`.** A noindex `/search` correctly absent from the docs sitemap was flagged as
   a missing utility route; the baseline expecting it was stale.
6. **A 200 OG image can still lie.** The share cards answered 200 at 1200x630 while saying "Open Source", "iOS", "100% Free".
   Preview checks must look at the card and grep the SVG masters for claims (discoverability lane D17).
7. **A remote that fetches only `main` hides a newer `gh-pages`.** `git rev-parse o/gh-pages` was stale; `git ls-remote o
   gh-pages` showed another session's deploy. Fetch `gh-pages:refs/remotes/o/gh-pages` explicitly before a manual Pages deploy.
