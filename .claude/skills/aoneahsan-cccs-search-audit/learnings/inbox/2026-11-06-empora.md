# Empora, 2026-11-06

- When a project moves tools to ZTools (`ztools-only.md`), the sitemap shrinks hard (72 to 22 URLs). Check the old URLs answer 301, not 404, and that the hub links render in the crawler body.
- `/pricing` crawler text comes from the same string as the meta description, so changing one intro changes three surfaces and the page-date ledger. A words gate should list all three.
- A date ledger that hashes "own words" missed words rendered through shared component strings (home cards): set `updated` by hand when those change, and make the ledger hash them.

## Lessons from the run's agents and verification (route on merge)

- Clean-install acceptance found what 87-of-87 tab sweeps could not: a sweep proves a page renders, not that it is true. Compare cards and switches against REST rows and read state back.
- A list drawn from a shared constant of "feature buckets" and matched to modules by key fails silently into "locked". Render from the server's rows.
- A switch whose state is never saved passes every gate. Grep for the state's reader.
- A zip that ships `source/` hashes the shared package too, so a words edit there changes the release hash. Keep marketing words in the web app's strings.
- `sideEffects: false` plus plain validators in route files took Empora's first-load JS from 361 to 240 KB gz. `validateSearch` and top-level schemas stay in the entry chunk even with auto code splitting.
- Lighthouse picks system Chrome unless `CHROME_PATH` is set to the automation binary.
- `pkill -f` and `pgrep -f` match the shell running the command; a bracket pattern does not help when the same command line also starts the program.
