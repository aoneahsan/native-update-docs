## 1. Proposed SA-P20 — a public page out of the sitemap with no robots signal (P2)

- **Seen:** production ClearHire. 27 registry routes with `access: 'public', indexed: false` (login, signup, settings,
  auth callback, error pages, id-lookup, progress, plus 12 aliases of indexed tool pages) answered 200 with the bare shell:
  no robots meta, no canonical, no `X-Robots-Tag` (evidence `live-signals.txt` before/after).
- **Cause:** "not in the sitemap" was the only exclusion. A sitemap's absence is not a directive, so any link to the page
  can get it indexed. The SPA shell gives the crawler nothing to read.
- **Detect:** list the registry's public non-indexed literal routes (or every public route absent from `sitemap.xml`),
  then `curl -sI` + raw-HTML grep each one for `X-Robots-Tag`, `name=robots` and `rel=canonical`. FAIL when none is present.
- **Fix:** from the host, so no JS is needed. An alias of an indexed page gets `Link: <twin>; rel="canonical"`, and every
  other page gets `X-Robots-Tag: noindex` (Firebase `hosting.headers`; Cloudflare `_headers`). Never `Disallow` as well.
  Add a contract test against the registry: exactly one signal per route, canonical targets are submitted pages, and no
  signal on a submitted page (ClearHire `src/features/seo/hosting.test.ts`).
- **Accept:** every such path shows its header live; submitted pages show neither.
- **Target:** `references/issue-catalogue.md` (new SA-P20), `aoneahsan-cccs-search-indexing` (noindex vs canonical table:
  "a route left out of the sitemap still needs its own signal").

## 2. Probe that lied — canon-sweep on minified Docusaurus (fixed in place)

- `https://clearhire-docs.aoneahsan.com/faq` serves `<link data-rh=true rel=canonical href=https://…/faq />` (no quotes).
  The old extractor `grep -oiE 'href=["'][^"']+'` returned an empty canonical for all 30 URLs, so all 30 read FAIL.
- **Fixed in place:** `references/probes.md` canon-sweep `href` match now accepts unquoted values (tested on both forms).

## 3. Probe that lied — `grep -c` on a one-line XML file (fixed in place)

- The ClearHire docs sitemap is one line, so `grep -c '<lastmod>'` printed 1 while 30 tags were present. It is the same
  trap the 2026-10-28 product audit hit (F-DISC-007). A note was added under canon-sweep in `references/probes.md`.

## 4. Calibration row stale (fixed in place)

## 5. Stack recipe — Firebase Hosting header globs

- `hosting.headers[].source` accepts the same `@(a|b)` extglob as rewrites (`/@(login|signup|settings)`,
  `/settings/@(plan|accessibility)`). One `Link` header per alias, since each has its own target. Verified live 2026-10-29.
