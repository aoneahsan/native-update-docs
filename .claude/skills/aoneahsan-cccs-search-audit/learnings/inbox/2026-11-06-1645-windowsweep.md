# Search audit lessons: windowsweep, 2026-11-06-1645 (session 23, release 1.4.3 deploys)

1. **A release cascade can miss the docs' own version constant (AI-07 + AI-05).** windowsweep-docs keeps
   `TOOL_VERSION` in `docusaurus.config.ts`; it drives the release gate, the `#software` JSON-LD `softwareVersion` and the
   discovery facts. The 1.4.3 cascade moved the product, site and changelog but left it at 1.4.2, and the
   `discovery-facts` guard passed, because it compares the node with the same constant. Found before publishing and
   fixed in docs `acfb7dd`. Check: compare the docs' `softwareVersion` with the newest `## [X.Y.Z]` in the docs
   changelog and with the product's `VERSION`, never with the constant that produced it. Target: `probes.md`
   (AI-05 version cross-read) and `-docusaurus` (the release checklist).
2. **A count in a navigation label goes stale (AI-07).** The docs footer said "Sections 0-25" after sections 26-29
   shipped in 1.4.0 (docs `acfb7dd`). A label with a range or count is a fact like any other: grep labels, footers
   and sidebars for numbers and cross-read them with the source of truth (`docs/sections.md`). Target:
   `issue-catalogue.md` AI-07 detection.
3. **Cloudflare Pages drops a `_headers` line over 2,000 characters, and says nothing.** On 2026-11-06 a 2,030-character
   CSP line shipped the site with no CSP at all (deploy `0035e46f`, rolled back). The same trap would drop an
   `X-Robots-Tag` or `Link` header rule written to `_headers`, so a `noindex` on `*.pages.dev` can vanish with a
   green deploy. Fix: fail the build on any `_headers` line over 2,000 characters (windowsweep-web
   `hosting/pages-output.ts`, watched failing on a planted 2,102-character line), and probe the served header on the
   live origin after every deploy. Target: `probes.md` (headers are read live, never from the file) and
   `-cloudflare-platform`.
