## 1. Wrong skill advice: docusaurus-search-local's noindex (fixed in place this run)

- **Target:** `references/issue-catalogue.md` → SA-P06 Fix (Docusaurus line). Also check `aoneahsan-cccs-docusaurus` and
  `aoneahsan-cccs-search-indexing` for the same assumption.
- **Evidence:** `https://rentparty-docs.aoneahsan.com/search` (2026-10-28) carried only
  `<meta data-rh=true property=robots content="noindex, follow"/>`, from `@easyops-cn/docusaurus-search-local@0.55.3`
  `SearchPage.jsx:85`. A robots meta is read from its `name`, so the page was indexable. A `grep robots` probe reports it as
  noindexed, so that probe lies.
- **Fix that worked:** `src/theme/SearchPage/index.tsx` wraps `@theme-original/SearchPage` and adds a `<Head>` with
  `<meta name="robots" content="noindex, follow">`. It is never Disallowed, so crawlers read the noindex. Verify that no other
  built page gained a noindex (`grep -rl 'name=robots content="noindex' build --include=*.html`). Docs `371495f`.
- **Corrected probe:** `curl -s <host>/search | grep -o '<meta[^>]*name=robots[^>]*>'`.
- **Fleet note:** every docs site on this plugin probably has the same defect. Run the corrected probe on each docs host in
  fleet mode.
